# 세상의 모든 밸런스 제품 리뷰 및 개선 설계

문서 버전: v1.0  
작성일: 2026-07-14  
검토 대상: `balance_all_product_spec.md`, `balance_all_upgrade_plan.md`  
검토 목표: 제품을 더 단순하고 재미있게 만들면서도, 사용자 제작 콘텐츠와 선택 데이터가 쌓여 지속적으로 재방문하는 구조를 확정한다.

### 검토 방법과 제한

- 로컬의 원본 제품 명세와 v2.1 업그레이드 기획을 기능, 사용자 흐름, 콘텐츠 공급, 리텐션과 운영 위험 관점에서 비교했다.
- 제공된 NotebookLM 노트북에는 검토 시점에 등록된 소스가 없어 답변 근거로 사용하지 않았다.
- 외부 근거는 플랫폼 공식 가이드, 공개 제품 실험과 학술 연구를 우선 사용했다.
- 본 문서의 수치 목표는 시장 규모 예측이 아니라 초기 가설을 기각하거나 유지하기 위한 실험 기준이다.

## 1. 결론

기존 기획의 핵심 아이디어는 유효하다. 다만 v2.1은 좋은 아이디어가 너무 많이 동시에 전면에 배치되어 제품의 첫인상이 흐려졌다. 제품을 다시 세 기능의 위계로 정리한다.

1. **본체 — 킬링타임 밸런스 게임:** 설명 없이 A/B를 고르고 즉시 결과를 보는 무한 덱
2. **축적 보상 — 나의 뇌:** 선택이 쌓일수록 가치관과 유형이 연결되는 개인 선택 지도
3. **콘텐츠 자급 — 세상에 물어보기:** 궁금한 일이나 친구·연인과 갈린 주제를 사용자가 직접 질문

제품의 최종 정의는 다음과 같다.

> **재미로 고르다 보면 나의 선택 지도가 자라고, 궁금한 것은 세상에 물어볼 수 있는 소셜 밸런스 게임.**

핵심 선순환은 다음과 같다.

```text
킬링타임으로 선택
  → 선택 데이터가 쌓여 나를 발견
  → 궁금한 질문을 직접 생성
  → 그 질문이 다른 사용자의 킬링타임 콘텐츠가 됨
  → 더 많은 선택 데이터와 질문이 쌓임
```

## 2. 목표 사용자와 제품 목표

### 2.1 핵심 사용자

- 1차 타깃: 밸런스게임, MBTI, 짧은 영상과 SNS 공유에 익숙한 18~29세
- 확장 타깃: 설명 없이 가볍게 A/B를 선택할 수 있는 전 연령 사용자
- 설계 원칙: 콘텐츠 감도는 젊게 유지하되 조작과 문구는 누구나 이해할 수 있게 한다.

### 2.2 최우선 목표

첫 출시 후 최우선 목표는 긴 세션이 아니라 **매일 다시 방문하는 습관**이다. 사용자는 원할 때 무제한으로 덱을 넘길 수 있지만, 앱을 다시 열 이유는 매일 갱신되는 대표 질문과 계속 달라지는 나의 뇌가 제공한다.

### 2.3 성공 경험

사용자가 첫 세션에서 다음 네 가지를 경험하면 제품 가설이 성립한다.

1. 3초 안에 첫 질문을 이해하고 선택한다.
2. 선택 직후 전체 결과와 자신의 위치를 확인한다.
3. 몇 번의 선택만으로도 나의 뇌가 자라고 있다는 신호를 본다.
4. 자신도 궁금한 질문을 올릴 수 있다는 사실을 이해한다.

## 3. 기존 기획의 강점

- A/B 선택은 설명이 필요 없고 참여 비용이 매우 낮다.
- 투표 소비와 질문 생산이 같은 포맷이라 UGC가 제품 본체에 바로 재사용된다.
- 선택 결과를 개인의 가치 데이터로 축적하는 발상은 일반 투표 앱과 구분된다.
- 친구·연인 사이의 논쟁을 공개 질문으로 바꾸면 실용성과 재미를 함께 만든다.
- AI를 전면에 내세우지 않고 작성 보조와 분류에 사용하는 방향은 적절하다.

## 4. 기존 v2.1의 핵심 문제

### 4.1 첫 화면에서 너무 많은 약속을 한다

무한 스와이프, 지금 고민, 데일리 질문, 예측 모드, 스트릭, 유형, 가치관 그래프, 미니미, 레어 초이스와 친구 비교가 모두 핵심처럼 제시되어 있다. 사용자는 첫 방문에 제품을 한 문장으로 이해하기 어렵고, 구현팀은 무엇의 완성도를 가장 높여야 하는지 판단하기 어렵다.

개선 원칙은 기능 삭제가 아니라 **점진적 공개**다. 첫 화면에는 질문과 A/B만 두고 결과, 나의 뇌, 작성, 공유를 행동 이후에 차례로 연다. Apple도 중요한 기능에 집중하고 필요한 내용만 먼저 보여주는 단순성과 위계를 권장한다.

### 4.2 예측 모드가 2초 리듬을 방해한다

다수파 예측과 실제 선택을 한 카드에서 연속으로 요구하면 한 번의 선택이 두 단계가 된다. 예측은 재미있는 이벤트가 될 수 있지만 기본 덱에 상시 적용하면 가장 강한 장점인 즉시성을 약화한다.

**판정:** 예측 모드는 P2의 주간 이벤트로 내린다.

### 4.3 무한 소비만으로는 다음 날 돌아올 이유가 약하다

무한 덱은 현재 세션을 늘리지만 끝이 없기 때문에 완료감과 내일의 기대를 만들기 어렵다. 반대로 하루 질문만 제공하면 사용자가 원하는 무제한 킬링타임과 충돌한다.

**판정:** `오늘의 대표 질문 1개`를 홈 첫 카드로 고정하고, 선택 후 무한 덱으로 이어지는 혼합 구조를 사용한다.

### 4.4 가치관 그래프가 너무 늦고 추상적이다

복잡한 노드 그래프는 데이터가 충분하지 않은 첫 세션에 빈 화면이 되기 쉽다. AI가 근거 없이 성격을 단정하면 신뢰도도 떨어진다.

**판정:** 첫 10개 선택까지는 8개 가치 축의 성장 애니메이션만 보여주고, 20개부터 유형과 연결 지도를 공개한다. 모든 인사이트에는 어떤 선택이 영향을 줬는지 확인할 수 있게 한다.

### 4.5 `클래식`과 `지금 고민`의 시스템 분리가 과하다

두 콘텐츠 모두 사용자 입장에서는 A와 B 중 하나를 고르는 질문이다. 별도의 작성 흐름, 마감 규칙과 화면을 만들면 이해와 구현 비용이 커진다.

**판정:** 작성 화면은 하나로 통합한다. `마감 없음`, `오늘 마감`, `직접 설정`만 선택적으로 제공한다. 피드에서는 마감 시간이 가까운 질문에만 카운트다운을 표시한다.

### 4.6 가짜 투표를 통한 반응 보장은 신뢰를 훼손한다

초기 시드 계정이나 운영 투표로 50표를 채우면 숫자의 의미와 서비스 신뢰가 무너진다.

**판정:** 보장 대상은 투표 수가 아니라 **노출 수**다. 새 질문에 최소 테스트 노출을 제공하고, 실제 반응이 없으면 작성자에게 솔직하게 알려 수정 또는 재게시 기회를 준다.

### 4.7 댓글을 너무 일찍 열면 운영 비용이 급증한다

연애·성별·돈·가치관 논쟁은 공격적인 댓글로 번지기 쉽다. 텍스트 댓글이 본체가 되면 투표 앱이 일반 커뮤니티로 변한다.

**판정:** P0에서는 구조화된 이유 칩과 신고만 제공한다. 자유 댓글은 신고·차단·검수 흐름을 준비한 뒤 P1에서 제한적으로 연다.

## 5. 승인된 제품 구조

### 5.1 화면 위계

하단 내비게이션은 네 개만 둔다.

1. **플레이:** 오늘의 대표 질문과 무한 A/B 덱
2. **물어보기:** 사용자 질문 작성과 내 질문 결과
3. **나의 뇌:** 가치관 축, 유형, 선택 기록
4. **마이:** 프로필, 저장, 설정, 신고·차단 관리

첫 실행은 내비게이션 설명이나 온보딩 슬라이드 없이 플레이의 첫 질문에서 시작한다.

### 5.2 플레이 루프

```text
오늘의 대표 질문
  → A/B 선택
  → 0.8초 결과 피드백
  → 다음 질문
  → 선택 데이터 축적 표시
  → 사용자가 원할 때 결과 상세 또는 나의 뇌 확인
```

#### 카드에 항상 보일 정보

- 질문 한 문장
- 선택 A와 B
- 카테고리 또는 `오늘의 질문` 배지
- 패스 버튼
- 신고 메뉴

#### 선택 후에만 보일 정보

- 전체 선택 비율
- `다수파`, `소수파`, `초접전` 중 하나의 짧은 상태
- 이유 칩 결과
- 공유와 상세 진입

작성자, 댓글 수, 저장 수, 가치 태그와 긴 설명은 기본 카드에서 숨긴다.

### 5.3 오늘의 대표 질문

- 매일 한 개를 운영자가 선정한다.
- 홈 첫 카드에 고정하지만 사용자는 패스할 수 있다.
- 선택 후 현재 결과를 바로 공개한다. 결과를 24시간 숨기는 복잡성은 MVP에서 제외한다.
- 다음 날에는 어제의 최종 결과 한 줄과 새로운 질문을 함께 보여준다.
- 스트릭 손실 압박 대신 `이번 주 4일 참여`처럼 누적 참여를 긍정적으로 표시한다.

### 5.4 사용자 질문 작성

필수 입력은 두 칸뿐이다.

```text
A: 여행 비용 정확히 반반
B: 소득에 따라 나누기
```

선택 입력은 다음과 같다.

- 상황 설명: 최대 120자
- 카테고리: 자동 제안 후 사용자가 변경
- 마감: 없음, 오늘, 직접 설정
- 공개 범위: 전체 공개 또는 링크로만 공개

AI는 사용자가 입력한 한 문장을 A/B로 다듬고 카테고리를 제안하는 보조 역할만 한다. 자동 게시하지 않으며 최종 문구는 사용자가 승인한다.

작성 후에는 첫 반응, 의미 있는 표본 도달, 마감 결과를 알린다. 고정 숫자 달성을 약속하지 않는다.

### 5.5 나의 뇌

#### 기본 가치 축

- 자유
- 안정
- 관계
- 현실
- 감성
- 성장
- 효율
- 재미

각 선택지는 운영 규칙 또는 검수된 자동 분류를 통해 1~2개의 가치 축에 연결한다. 사용자는 결과 상세에서 `이 선택이 자유와 재미에 반영됨`처럼 계산 근거를 확인할 수 있다.

#### 공개 단계

- 1~9개 선택: 뇌가 깨어나는 진행 표시
- 10~19개 선택: 상위 가치 축 3개와 최근 변화 공개
- 20개 이상: 유형 이름과 단순 연결 지도 공개
- 50개 이상: 주제별 차이와 주간 변화 공개

유형은 영구 진단이 아니라 현재 선택 데이터의 요약으로 표현한다. `당신은 원래 이런 사람` 대신 `최근 선택에서는 이런 경향`이라는 문구를 사용한다.

### 5.6 친구·연인과의 논쟁

모든 공개 질문에는 공유 링크가 생긴다. 링크를 받은 사람은 가입 전에 한 번 선택할 수 있고, 선택 후 전체 결과를 본다. 링크 전용 질문은 공개 덱에 섞이지 않는다.

친구 비교와 궁합 점수는 P1로 둔다. MVP에서는 같은 질문에 각자 무엇을 골랐는지만 공유 화면에서 확인한다.

## 6. 콘텐츠가 스스로 순환하는 구조

운영자가 모든 질문을 계속 만들지 않도록 공급원을 세 가지로 나눈다.

### 6.1 운영 콘텐츠

- 출시 전 검수된 상시 질문 300개를 준비한다.
- 이후 운영자가 직접 만드는 콘텐츠는 오늘의 대표 질문 하루 1개를 원칙으로 한다.
- 대표 질문은 구체적이고 누구나 즉시 장면을 떠올릴 수 있어야 한다.

### 6.2 사용자 콘텐츠

- 새 질문은 우선 작은 테스트 트래픽에 노출한다.
- 선택률이 높고 패스·신고율이 낮으면 더 넓게 배포한다.
- 반응이 약하면 작성자에게 제목 수정 또는 선택지 균형 조정을 제안한다.
- 같은 질문의 중복은 작성 전에 유사 질문을 보여주고 `내 상황으로 바꾸기` 리믹스를 제공한다.

### 6.3 초기 덱 구성 가설

- 검수된 상시 질문 50%
- 반응이 검증된 사용자 질문 30%
- 신규 사용자 질문 테스트 15%
- 오늘의 질문과 시간 제한 질문 5%

이 비율은 고정 규칙이 아니라 초기 실험값이다. 신규 질문의 최소 노출과 전체 덱 품질을 동시에 보호하는 것이 목적이다.

### 6.4 질문 품질 기준

좋은 질문은 다음 조건을 만족한다.

- 두 선택지가 서로 배타적이고 균형이 맞는다.
- 3초 안에 이해된다.
- 구체적인 상황이 떠오른다.
- 정답을 강요하거나 특정 집단을 모욕하지 않는다.
- 선택 결과가 궁금하다.

## 7. 기능 우선순위 재정리

### P0 — 제품 가설 검증에 필수

- 게스트 상태에서 즉시 첫 투표
- 오늘의 대표 질문 1개
- 무한 A/B 카드 덱과 패스
- 선택 직후 비율과 짧은 피드백
- 통합 질문 작성 화면
- 신규 질문 테스트 배급
- 이유 칩, 신고, 차단
- 선택 데이터 저장
- 나의 뇌 진행 표시와 20개 선택 후 기본 유형
- 공개 질문 및 링크 전용 질문 공유
- 첫 반응과 결과 알림

### P1 — 핵심 루프가 검증된 뒤

- 자유 댓글과 댓글 운영 도구
- 친구 선택 비교와 간단한 궁합
- 주간 나의 뇌 변화 카드
- 유형 공유 이미지
- AI 질문 다듬기와 중복 질문 추천
- 관심 카테고리 기반 개인화
- 작성자 후일담

### P2 — 차별화 확장 실험

- 예측 챌린지
- 미니미 또는 캐릭터 표현
- 레어 선택 컬렉션
- 월간 리와인드
- 그룹 전용 질문방
- 랭킹과 시즌 이벤트

### 삭제 또는 보류

- 가짜 계정·운영 투표를 통한 표 수 부풀리기
- 기본 덱의 상시 예측 2단계

- 근거 없이 성격을 단정하는 AI 인사이트
- 텍스트 댓글을 중심으로 한 일반 커뮤니티화

## 8. 지표 체계

### 8.1 최우선 지표

**첫 방문자 중 7일 안에 3일 이상 투표한 사용자 비율**을 초기 핵심 지표로 둔다. 단순 D7 접속 여부보다 실제 선택 습관이 생겼는지 측정하기 쉽다.

### 8.2 재방문 지표

- D1, D7 투표 리텐션
- 오늘의 대표 질문 참여율
- 첫 주 활동 일수 분포
- 나의 뇌를 확인한 사용자의 다음 날 재방문율

### 8.3 본체 재미 지표

- 첫 화면에서 첫 투표까지 걸린 시간
- 세션당 투표 수 중앙값
- 질문별 패스율
- 10개 선택 도달률
- 결과 상세 진입률

### 8.4 콘텐츠 자급 지표

- 활성 사용자 대비 질문 작성자 비율
- 새 질문의 첫 실제 투표까지 걸린 시간
- 질문당 실제 투표 수 중앙값
- 첫 질문 작성자의 14일 내 재작성률
- 사용자 제작 질문이 전체 유효 투표에서 차지하는 비율
- 중복·신고·숨김 처리 비율

### 8.5 나의 뇌 지표

- 20개 선택 도달률
- 유형 공개 후 공유율
- 나의 뇌 주간 재방문율
- 인사이트 근거 보기 비율
- 유형이 부정확하다는 피드백 비율

### 8.6 보호 지표

- 신고율과 차단율
- 공격적 질문 자동 차단의 오탐률
- 알림 해제율
- 긴 세션 이후 다음 날 이탈률
- 질문 작성 후 반응을 받지 못한 사용자 비율

세션 길이는 참고 지표로만 사용한다. 사용자를 오래 붙잡는 것보다 만족스럽게 선택하고 다시 돌아오는 것이 우선이다.

## 9. 검증 계획

### 1단계 — 핵심 손맛 검증

- 카드 30개로 클릭 가능한 프로토타입을 만든다.
- 18~29세 중심 사용자 10명과 확장 연령 사용자 5명에게 설명 없이 사용하게 한다.
- 첫 투표 시간, 10개 도달률, 멈춘 이유를 관찰한다.
- 통과 기준: 참가자 15명 중 12명 이상이 설명 없이 첫 투표를 완료하고, 10명 이상이 자발적으로 10개 이상 선택한다.

### 2단계 — 콘텐츠 품질 검증

- 상시 질문 300개를 품질 기준에 따라 검수한다.
- 사용자 질문 작성과 소규모 테스트 배급을 연다.
- 패스율 상위 질문의 공통 문제를 분류해 작성 보조 문구에 반영한다.
- 통과 기준: 사용자 제작 질문의 중앙 패스율이 운영 질문 대비 15%포인트 이상 나쁘지 않다.

### 3단계 — 재방문 검증

- 오늘의 대표 질문과 나의 뇌 진행 표시를 각각 기능 플래그로 운영한다.
- 기본 덱만 있는 집단, 오늘의 질문 집단, 오늘의 질문과 나의 뇌 집단을 비교한다.
- 통과 기준: 오늘의 질문과 나의 뇌 집단의 `7일 내 3일 이상 투표율`이 기본 덱 집단보다 상대적으로 15% 이상 높다.

### 4단계 — 질문 생산 선순환 검증

- 10개 선택 후 질문 작성 제안과 항상 보이는 작성 탭의 성과를 비교한다.
- 질문을 올린 사용자의 재방문과 재작성률을 측정한다.
- 통과 기준: 신규 질문의 90% 이상이 24시간 안에 실제 사용자 투표 10개 이상을 받고, 첫 작성자의 14일 내 재작성률이 20% 이상이다.

### 5단계 — 공유 유입 검증

- 공개 질문 링크와 유형 공유 카드의 유입 품질을 비교한다.
- 비회원은 링크에서 먼저 투표하고 결과 확인 뒤에만 가입을 제안한다.
- 통과 기준: 공유 링크 방문자의 투표 완료율 60% 이상, 투표 완료자의 가입 전환율 15% 이상이다.

수치는 사업 성과 예측이 아니라 초기 제품 판단을 위한 실험 기준이다. 실제 데이터가 쌓이면 코호트별 기준을 다시 설정한다.

## 10. 안전·신뢰 원칙

- 미성년자, 성적 내용, 혐오, 자해, 범죄와 개인정보 노출 질문에 별도 정책을 적용한다.
- 공개 질문에는 실명, 학교, 회사, 연락처 등 특정 가능한 정보를 쓰지 못하게 한다.
- 연애와 관계 질문에서 특정 상대를 비난하거나 신상을 유추할 수 있는 서술을 제한한다.
- 투표 수와 비율은 실제 데이터만 사용한다.
- 나의 뇌는 오락과 자기 성찰 도구이며 전문 심리 진단이 아님을 명시한다.
- 사용자는 자신의 선택 기록과 유형 계산 데이터를 삭제할 수 있어야 한다.
- 알림은 첫 반응, 의미 있는 표본, 마감 결과로 제한하고 세부 알림을 끌 수 있게 한다.

## 11. 외부 조사에서 반영한 근거

1. Apple Human Interface Guidelines는 가장 중요한 기능에 집중하고, 필요한 요소만 먼저 보여주며 복잡성을 점진적으로 공개할 것을 권장한다. 이 원칙을 첫 화면의 질문·A/B 집중과 나머지 정보의 후속 공개에 적용했다.  
   <https://developer.apple.com/design/human-interface-guidelines/design-principles>

2. Duolingo는 스트릭 유지 조건을 한 번의 학습으로 낮춘 실험에서 D14 리텐션이 상대적으로 3.3% 증가했다고 공개했다. 매일의 핵심 행동을 쉽게 시작하게 해야 한다는 근거로 사용했다.  
   <https://blog.duolingo.com/improving-the-streak/>

3. 모바일 게임의 무작위 현장 실험에서는 사용자 콘텐츠 제출이 세션 종료 위험을 약 11%, 앱 이탈 위험을 14% 줄였고, 사용자 콘텐츠 소비도 앱 이탈 위험을 13% 줄였다. 반면 두 기능의 상호작용은 참여에 부정적일 수 있었다. 작성과 소비를 모두 유지하되 첫 화면에서 경쟁시키지 않는 이유다.  
   <https://doi.org/10.1287/mnsc.2020.3943>

4. Google Research는 단기 참여량만 최적화하기보다 장기 재방문과 연관된 행동 신호를 찾아야 한다고 제안한다. 세션 길이 대신 반복 투표 일수를 최우선 지표로 둔 근거다.  
   <https://research.google/pubs/surrogate-for-long-term-user-experience-in-recommender-systems/>

5. 2025년 스마트폰 앱 현장 실험은 행동 설계가 사용 시간을 늘릴 수 있지만, 사용자에게 조절권을 제공하면 사용 시간은 줄고 지불 의향은 높아질 수 있음을 보고했다. 무한 덱을 허용하되 패스, 알림 설정과 투명한 결과를 제공하는 보호 원칙에 반영했다.  
   <https://doi.org/10.1016/j.euroecorev.2025.105230>

## 12. 최종 제품 원칙

1. 첫 화면에서는 고르게 하고 설명하지 않는다.
2. 선택 직후에는 숫자보다 `나는 어디에 속했는가`를 보여준다.
3. 선택이 쌓이는 이유를 나의 뇌가 설명한다.
4. 사용자의 질문이 다른 사용자의 놀이가 되게 한다.
5. 운영자는 모든 질문이 아니라 오늘의 한 질문의 품질에 집중한다.
6. 기능은 본체의 선택 리듬을 깨지 않을 때만 추가한다.
7. 체류 시간보다 만족스러운 재방문을 최적화한다.

## 13. 최종 판정

기존 v2.1은 폐기 대상이 아니라 **재배치 대상**이다.

- 유지: 무한 선택 덱, 오늘의 질문, 사용자 작성, 가치관 데이터, 나의 뇌, 공유
- 단순화: 클래식/지금 고민 통합, 결과 화면, 작성 입력, 그래프 공개 단계
- 후순위: 예측, 미니미, 레어 컬렉션, 친구 궁합, 월간 리와인드
- 제거: 가짜 투표, 손실형 스트릭 압박, 근거 없는 AI 성격 단정

이 재배치가 완료되면 제품의 첫인상은 단순해지고, 사용할수록 깊어지며, 사용자 질문을 통해 콘텐츠가 스스로 순환한다.
