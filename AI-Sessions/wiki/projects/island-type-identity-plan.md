# "넌 무슨 섬이야?" — 섬 타입 정체성 시스템 계획서

## 한 줄 요약

MBTI처럼 **"넌 무슨 섬이야?"**가 사회적 화폐가 되려면, 지금의 *각자 자라는 개인 섬*(연속적·고유) 위에
**16개의 이름 있는 '섬 타입'(이산적·공유)**을 얹어야 한다. 정체성·소속감·궁합·공유 카드가 핵심 엔진이다.

## 왜 지금은 안 되는가 (현재 시스템 진단)

| 현재 | MBTI가 바이럴인 이유와의 격차 |
|---|---|
| `islands` = 카테고리별 trait로 잠금 해제되는 **장소**, `productCopy`의 "나의 성향 섬 Lv.N"은 **개인이 자라는 섬** | MBTI는 **이산적·공유 타입**(16칸, 4글자 코드). 모두가 같은 어휘로 비교 가능 |
| 성향 = 5축 **연속 점수 + 펫 매칭 + 모순 지도**(깊이 있음) | 공유 어휘·"우리(INTJ들)" 소속감·즉석 궁합 신호가 **없음** |
| 결과가 개인화돼 **공유 한 줄로 압축 불가** | "난 ○○ 섬이야" 한마디로 정체성·궁합을 즉시 시그널 |

→ 현재 앱은 **자기발견(깊이)**엔 강하지만 **사회적 정체성(전파)**엔 약하다. 둘 다 필요하다.

## 자료 수집 요약 (왜 MBTI가 한국에서 폭발했나 → 설계 원칙)

웹/커뮤니티 조사에서 추출한 바이럴 동인:

1. **소속 불안 해소**: 한국인은 어느 집단에도 속하지 않으면 불안 → 명확한 타입이 '소속'을 줌. (CNN, inspirethemind)
2. **불확실성 시대의 단순화**: VUCA 시대에 "4글자 코드"가 안정감을 줌 — 복잡한 나를 단순·고정된 것으로. (Korea Times)
3. **사회적 화폐**: 긴 자기설명 없이 타입 한마디로 **궁합·성향을 즉석 시그널**. (medium "social currency")
4. **궁합(연애/소개팅)이 최대 전파 엔진**: 더쿠·인스티즈·디시에서 MBTI 궁합·소개팅 짤이 가장 많이 공유됨. 'N/S 차이'가 관계의 핵심 화두. (namu MBTI소개팅, 더쿠 바이럴 사례 2022)
5. **공유성**: 결과 = 무료 바이럴 콘텐츠. 인스타 스토리/캡처로 친구망에 전파. (16personalities 월 1,590만 방문)
6. **체감 정확도("이거 완전 나야")**: 디테일한 프로필이 '이해받는 느낌'을 줌.
7. **방송·연예인·짤 모멘텀**: 예능이 MBTI를 소재화 → 밈·연예인 유형 분석이 바이럴.

## 핵심 설계: 3층 구조 — 4 군도 → 16 섬 → 오늘의 날씨

> 🔬 **deep-research2 검증 반영**: 단순 "16타입 얹기"는 약하다. 16personalities도 16개를 4 Role로 묶고, 같은 타입에 변주를 둔다.
> 사람은 불확실할수록 **경계 분명한 집단**에 강하게 동일시 → **군도(4) → 섬(16) → 상태(날씨)** 3층이 가장 강하다.

**① 정체성 4축 → 16 섬** (이미 있는 5축 중 4개를 정체성 코어로):

| Balance 축 | 인지 대응 | UI 카피 권장(MBTI 직역 금지) |
|---|---|---|
| `solo ↔ social` | 에너지 방향(I↔E) | 혼자 충전 ↔ 함께 충전 |
| `comfort ↔ curious` | 정보 취향(S↔N 유사) | **사실형 ↔ 가능성형**(S/N 직역은 피함) |
| `calm ↔ express` | 표현 방식 | **담담형 ↔ 표현형** (※ T/F 직역 금지 — MBTI T/F는 '판단 기준'이지 감정 표현량이 아님) |
| `plan ↔ flow` | 외부 대응(J↔P) | 계획형 ↔ 즉흥형 |

→ 4축 우세극 조합 = **2⁴ = 16 섬**. 각 섬에 이름·이모지·색·한 줄 정체성·페르소나.

**② 5번째 축 `safe ↔ adventure` = "항해 스타일" 수식어**(16P의 -A/-T 자리이되 의미는 다름):
- ⚠️ 16P의 -A/-T(Assertive/Turbulent)는 모험심이 아니라 **자기확신·스트레스 반응**. `safe↔adventure`를 -A/-T라 부르면 의미가 어긋난다.
- 그래서 별도 **자사 IP 언어**로 분리: **정박형 ↔ 원정형** ("○○ 섬 · 원정형"). 16P를 닮되 베끼지 않고 섬 세계관에 자연스럽게 붙음.

**③ 4 군도**(16섬을 외우기 전에 큰 소속감부터):
- 16섬을 4개 군도로 묶음(예: 탐험 군도 / 등대 군도 / 광장 군도 / 작업실 군도 — 네이밍은 콘텐츠 작업).
- "난 탐험 군도 사람이야"가 먼저 형성 → 섬 네이밍을 다듬는 동안에도 커뮤니티·밈 운영이 쉬움.

**④ 오늘의 날씨**(영구 정체성 ≠ 매일 변하는 상태):
- 영구 섬은 고정(정체성 안정), 최근 답변·행동으로 **잔잔함/역풍/만조/파문** 같은 날씨 상태를 매일 부여.
- 타입 일관성을 깨지 않으면서 매일 열어볼 이유 + 연속 깊이 지도와 연결. (성격은 고정값이 아니라 역동적 — APA/16P도 "경향이지 규칙 아님" 명시 → 가드레일과 일치.)

**노출 원칙: 이름 전면, 코드 뒷면.** 한국 성향 밈은 코드("SCFP-A")보다 **이름 있는 라벨**("축제섬 원정형")로 이동(에겐/테토, "너 T야?"). 코드는 궁합 계산·분석 페이지 보조로만.

- 예시 네이밍(초안):
  - social·curious·express·flow → **🎡 축제의 섬** ("처음 보는 사람이랑도 30분이면 친구")
  - solo·comfort·calm·plan → **🗼 등대의 섬** ("말 없이 곁을 지키는 사람")
  - solo·curious·calm·plan → **🔭 탐구의 섬** ("혼자 끝까지 파고드는 분석가")
  - social·comfort·express·plan → **🏡 마을회관의 섬** ("사람들을 챙기고 모으는 구심점")
  - (전체 16섬 + 4군도 네이밍/페르소나는 별도 콘텐츠 작업)

**핵심: 이산 타입(전파) + 기존 연속 지도/펫(깊이)를 둘 다 유지.** 16personalities도 "INTJ-A(건축가)"라는 이산 정체성 + 상세 프로필(깊이)을 함께 준다.

## 바이럴 엔진 (자료 기반 우선순위, deep-research2 검증 반영)

> 북극성 지표 = "콘텐츠 수"가 아니라 **한 사용자가 24시간 안에 만든 외부 연결 수**. 결과도달률·저장/공유율·친구초대 전환율·궁합 진입률·같은섬 재방문률을 먼저 본다.

### 1. 궁합 = "관계 사용설명서"(점수표 아님) — 최우선, 한국 전파 1위 엔진
- 연애/친구/일 **궁합을 분리**, **베스트 / 도전 항로**만 공개(워스트·문제타입 같은 낙인 표현 금지).
- ⚠️ 핵심: 퍼가는 건 "88점"이 아니라 **생활 문장**("이 섬은 싸울 때 바로 답 안 하면 더 불안해함"). 숫자는 첫 화면 호기심, **카피가 저장·공유**를 만든다.
- 진입: "내 섬과 잘 맞는 섬", "@친구 코드 → 우리 궁합".
- 데이터: `island_type_compat(type_a, type_b, romance_blurb, friend_blurb, work_blurb)` (축 거리 자동 산출 + 카피 큐레이션).

### 2. "친구가 보는 내 섬" — 초대 루프 + 바넘효과 방어 (강력 추천)
- 결과 화면에 **"친구 3명에게 물어보기"** → 친구가 나를 어느 섬으로 보는지 투표 → "내가 본 나 vs 남이 본 나" 비교.
- 효과: ① 친구 초대 = 자연 유입 루프, ② 결과가 독백이 아니라 **관계 속 피드백**이라 "이거 완전 나야"의 신뢰가 올라가고 바넘효과 비판도 완화.

### 3. 공유 카드 — 자기표현물(정보 카드 아님)
- 공유는 "내 타입 결과"보다 **친구가 저장하고 싶은 말투 + 자랑 가능한 희소성 + 태그하기 좋은 관계 한 줄**일 때 퍼진다(자기표현 동기 = 공유 예측).
- 기존 **WeeklyRecap(Wrapped식)·view-shot 인프라 재사용**. "나는 🎡 축제의 섬 · 원정형 (상위 12%)" + 한 줄 정체성 + 궁합 베스트. 딥링크로 설치 유입.

### 4. 파생 미니 테스트 연속 발행 — 진짜 볼륨은 여기서
- 코어 IP(섬 결과) 하나만 내지 말고, 직후부터 **1축·1맥락 파생 퀴즈**를 계속 발행: "나를 연애할 때 사용설명서", "친구로 친해지는 법", "일할 때 나는 어떤 선배?".
- 기존 카테고리/질문뱅크·trait 인프라 재사용 → 저비용으로 양산. (참고: 크래프톤 'MBTI 소개팅'이 큰 건 궁합 점수가 아니라 "16명과 가상 소개팅 서사"였음.)

### 5. 소속감·인구 통계 + 밈 — 소속 불안 해소 / 모멘텀
- "같은 섬 사람 N명", "내 섬 인구 비율", "이번 주 인구 많은 섬" 랭킹.
- 섬별 **"특징 한 줄/밈 카드"**("○○ 섬 특)" 템플릿), 연예인·캐릭터 섬 사전(기존 `characters` 재활용) — 단 **진실 판정이 아니라 팬덤형 해석 놀이**로 운영(공식 인증처럼 보이지 않게).

## 현재 시스템과의 통합 (버리지 않고 층을 나눔)

| 층 | 역할 | 현재 자산 활용 |
|---|---|---|
| **정체성 층(신규)** | 16 섬 타입 = 공유·전파·궁합 | 5축 trait 점수에서 우세극 산출 |
| **깊이 층(기존)** | 연속 trait 지도·모순·펫 = 자기발견·리텐션 | insight map, `assign_personality_pet`, 모순 카드 그대로 |
| **성장 층(기존)** | "내 섬 Lv" = 선택 누적으로 정밀해짐 | productCopy "섬 Lv", choice echo |

UX: 온보딩에서 **N문항 풀면 "당신은 ○○ 섬!"**(빠른 정체성·훅) → 이후 계속 풀수록 깊이 층이 정교해지고 타입 신뢰도(%)가 올라감("아직 ○○ 섬에 가까워요, 5개 더 풀면 확정").

## 데이터 모델 / 구현 단계

- **D1. 타입 산출 RPC** `compute_user_island_type(uid)`: user_traits → 4축 우세극 → 16섬 코드 + 군도 + 항해수식어(정박/원정) + 날씨 + 신뢰도(표본수).
- **D2. 타입 카탈로그** `island_types(code, name, emoji, color, archipelago, tagline, persona, romance_blurb, friend_blurb, work_blurb)` 시드(16섬 + 4군도, 콘텐츠).
- **D3. 궁합** `island_type_compat`(연애/친구/일 blurb) + `compute_pair_compat(a,b)`. **점수보다 생활문장 카피 우선.**
- **D3.5 그룹 궁합** `compute_group_compat(uid[])` → 3~8인 군도 구성 + 한 줄 해설.
- **D4. 집계형 소속감(저위험·우선)**: `fetch_feed_questions`에 **섬별 응답 분포** 조인("축제섬 87% B"). 인구 통계 뷰(타입별 비율, 캐싱).
- **D5. "친구가 보는 내 섬"**: 친구 투표 수집 RPC + "내가 본 나 vs 남이 본 나" 비교.
- **D6. 화면**: ① 결과/정체성(섬 카드) ② 궁합(관계 사용설명서) ③ 공유 카드(view-shot 재사용) ④ 파생 미니테스트 ⑤ 같은섬 분포/방명록.
- **단계(네트워크형)**: **P0** = D1·D2·결과화면 **+ 저장카드 + 친구에게 물어보기**(한 화면에 전파 루프) → **P1** = 궁합(사용설명서)·파생 미니테스트 → **P2** = 집계형 소속감(피드 분포)·밈·라이트 방명록·그룹 궁합.

## 같은 섬·같은 성향 커뮤니티 / 공유 방향 (사용자 질문 반영)

소속감은 이 앱의 **1순위 동인**(불안할수록 분명한 집단에 동일시)이라 "같은 섬 사람끼리"는 방향이 맞다.
다만 유형 게시판·랜덤채팅을 처음부터 무겁게 열면 **배타성·낙인·콜드스타트·모더레이션 비용**이 크다 → **가벼운 것부터, 단계적으로.**

### 권장: 무거운 커뮤니티보다 "집계형 소속감"부터 (저비용·저위험·고효과)
- **섬별 응답 분포를 기존 피드에 얹기**(신규 기능 거의 없이 즉시 가능, 가장 강력):
  - 각 질문 결과에 *"🎡 축제의 섬 사람들은 87%가 B를 골랐어요 · 당신도 B!"* 표시.
  - 효과: 투표할 때마다 **"나 같은 사람들"을 확인** → 소속감·체감정확도를 매 선택마다 강화. 모더레이션 불필요(집계라 개인 노출 없음). 기존 `fetch_feed_questions`/votes에 섬 타입 조인만 추가.
- **섬 vs 섬 친선 구도**: "이 질문, 등대섬 vs 축제섬 어디가 더 갈렸을까?" 같은 집계 대결(개인이 아니라 집단 단위 → 안전).

### 라이트 커뮤니티(P2): 비동기·익명 우선
- **같은 섬 한 줄 방명록**(가벼운 async): "축제섬 다녀감 ✋", 좋아요만. 실시간 채팅·DM은 후순위(독성·모더레이션 위험).
- **"○○ 섬 특)" 밈 템플릿** + 같은 섬 인기 밈 피드. (기존 사용자 질문 제출/피드 인프라 + 악용 방어 L1~L3 그대로 재사용 → 안전망 이미 있음.)
- **그룹 궁합 "우리 모임 군도 지도"**: 친구/팀 3~8인을 묶어 "등대섬 2·축제섬 3·탐구섬 1 → 회의는 재밌지만 마감 전날 피곤" 분석. 연애보다 가볍고 친구·회사·동아리까지 범용 → 캡처 공유 잘 됨.

### 커뮤니티 단계 / 가드레일
- **단계**: 집계형 소속감(피드 분포) → 방명록·밈(비동기) → (수요 확인 후) 유형 채널. 처음부터 게시판/랜덤채팅 X.
- **반-배타성**: "우리 섬 우월" 프레이밍 금지. 섬 간 **친선·상호보완**으로 카피. 워스트→**도전 항로**, 문제타입→**마찰 포인트**.
- **모더레이션 저부담 설계**: 자유서술보다 **스탬프·집계·템플릿** 위주(독성 표면적 최소화). 자유 텍스트는 기존 제출 큐 검수·익명 흐름 준수.

## 리스크 / 가드레일

- **바넘효과·과신**: "과학·진단"이 아니라 **"취향 발견·관계 이해 놀이"**로 프레이밍(법적·윤리). MBTI 재단·16P·APA 모두 "경향이지 규칙 아님" 명시 → 같은 톤. "친구가 보는 나"로 독백→피드백 전환해 방어.
- **이산화 뉘앙스 손실**: 깊이 층(연속 지도·모순 카드)을 **반드시 병행**. 타입은 훅, 지도는 진실.
- **카피 규칙(낙인 방지)**: 워스트 궁합→**도전 항로**, 문제 타입→**마찰 포인트**, "너는 원래 이런 사람"→**"이런 경향이 있어 보인다"**.
- **채용 오남용 차단**: 자료상 채용에 MBTI 쓰는 건 부적절(43%)이 적절(26%)보다 높음. 섬 타입을 **선발·평가 용도로 쓰지 않게** 톤/문구 관리.
- **에겐/테토 교훈**: 자연어 라벨은 빨리 퍼지지만 **과단순화·젠더 고정관념** 비판을 받음. 성별·외모 결정론적 카피 금지.
- **표본 부족 시 단정 금지**: 신뢰도% + "5개 더 풀면 확정" 게이팅.
- **차별점은 "타입을 만든 것"이 아니라 "섬 세계관으로 정체성을 운영"하는 것**: 구조는 MBTI에서 배우되, **언어·세계관은 섬 자사 IP**로(정박/원정, 군도, 날씨) — "MBTI 아류" 회피.
