# Run-Ready Expo App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Balance Island Expo app installable, connected to a user-authenticated Supabase project, compilable, and viewable in a browser through Expo Web with Browser/Chrome-style verification.

**Architecture:** First create the missing Expo Router shell and project config, then replace parser-blocking corrupted TSX with stable UTF-8 screen implementations. Use Browser/Chrome tooling to open Supabase and Google developer consoles while the user performs login/2FA directly; after authentication, enter required public configuration into local `.env` and verify the app against the live project.

**Tech Stack:** Expo SDK 51, Expo Router 3, React Native 0.74, TypeScript, Zustand, Supabase JS, expo-image, Browser plugin for localhost verification.

## Scope

This plan is for the first launchable milestone only. It does not complete production RLS, Supabase migrations, OpenAI billing controls, or full server-side transaction refactors. Those remain tracked in `research.md`.

Success means:

- `npm.cmd install` completes and creates a lockfile.
- User completes Supabase and, if needed, Google authentication in the opened browser session.
- `.env` contains real `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` values.
- Supabase schema is applied or a compatible project schema is confirmed.
- `npm.cmd run web` starts Expo Web.
- Browser can open the local Expo URL.
- The app renders a tab shell with Feed, Create, Island, and Profile.
- No parser-level syntax errors remain in route/component/service files.
- `timeline.md` and `research.md` are updated with the new verified state.

## User-Authenticated Console Rule

The user explicitly wants to perform Supabase and Google developer authentication themselves while the agent drives the browser after login. Follow this rule for all console work:

- Use the Browser plugin, and Chrome plugin if callable in the active environment, to open the relevant console pages.
- Make the browser visible during login/authentication.
- Pause while the user enters credentials, completes SSO, 2FA, organization selection, billing prompts, or consent screens.
- After the user confirms they are authenticated, the agent may click through project settings, copy public configuration values, and enter them into local files or web forms.
- Never ask the user to send secrets in chat.
- Never store service role keys, OpenAI API keys, Google client secrets, passwords, or recovery codes in committed files.
- Public Supabase anon key and project URL may be written to local `.env`; `.env` must stay untracked.

## External Review Validation

The external review report at `C:\Users\petbl\.gemini\antigravity\brain\069a60aa-b05f-40e9-ba0a-53884ace658d\review_report.md` was checked against the current codebase and this plan.

Accepted as technically valid and incorporated:

- Parser-blocking UTF-8/JSX/string corruption exists in current TSX/SQL files. This plan already prioritizes parser-safe rewrites before launch.
- Expo Router shell files are missing. This plan already creates `src/app/_layout.tsx` and `src/app/(tabs)/_layout.tsx`.
- `supabase/schema.sql` currently contains destructive `DROP TABLE ... CASCADE` statements. This plan now forbids applying that reset script to the live Supabase project and adds a live migration gate.
- RLS and policies are absent from the current schema. This plan now requires run-ready RLS policies before live browser verification.
- `auth.users` to `public.profiles` auto-creation is absent. This plan now requires a profile creation trigger before auth testing.
- Client-side vote/reaction multi-table updates are unsafe for live use. This plan now requires `submit_vote` and `submit_reaction` RPCs and updates service implementation to call them.
- `query.not('id', 'in', ...)` with hand-built UUID lists is fragile. This plan now routes feed retrieval through a server RPC instead of client-composed `NOT IN`.
- Whole-array optimistic rollback in Zustand is too broad. This plan now narrows rollback to the affected question.
- `expo-image` prefetch signature must be verified against installed types. This remains in Browser/TypeScript verification and is now called out as a specific check.

Not incorporated as a separate new task:

- The report repeats the encoding and router issues already covered by Task 2, Task 4, and Task 6, so those are not duplicated.
- Production-grade schema migration history is out of scope for the immediate run-ready milestone, but destructive reset separation and a non-destructive live migration are now required before applying anything to Supabase.

CREATE OR REPLACE FUNCTION public.fetch_feed_questions(
  p_limit integer DEFAULT 30,
  p_cursor_created_at timestamptz DEFAULT NULL
)
RETURNS TABLE (
  id uuid,
  title text,
  description text,
  category_id uuid,
  category jsonb,
  tags text[],
  option_a_title text,
  option_a_description text,
  option_a_image_url text,
  option_b_title text,
  option_b_description text,
  option_b_image_url text,
  vote_count_a integer,
  vote_count_b integer,
  reaction_like_count integer,
  reaction_fun_count integer,
  reaction_hard_count integer,
  comment_count integer,
  created_at timestamptz
)
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT
    q.id,
    q.title,
    q.description,
    q.category_id,
    jsonb_build_object(
      'id', c.id,
      'name', c.name,
      'slug', c.slug,
      'color', c.color
    ) AS category,
    q.tags,
    q.option_a_title,
    q.option_a_description,
    q.option_a_image_url,
    q.option_b_title,
    q.option_b_description,
    q.option_b_image_url,
    q.vote_count_a,
    q.vote_count_b,
    q.reaction_like_count,
    q.reaction_fun_count,
    q.reaction_hard_count,
    q.comment_count,
    q.created_at
  FROM public.questions q
  LEFT JOIN public.categories c ON c.id = q.category_id
  WHERE q.status = 'approved'
    AND (p_cursor_created_at IS NULL OR q.created_at < p_cursor_created_at)
    AND (
      auth.uid() IS NULL
      OR NOT EXISTS (
        SELECT 1
        FROM public.votes v
        WHERE v.question_id = q.id
          AND v.user_id = auth.uid()
      )
    )
  ORDER BY q.heat_score DESC NULLS LAST, q.created_at DESC
  LIMIT LEAST(GREATEST(p_limit, 1), 50);
$$;

CREATE OR REPLACE FUNCTION public.submit_vote(
  p_question_id uuid,
  p_selected_option text,
  p_response_time_ms integer DEFAULT NULL
)
RETURNS public.votes
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  inserted_vote public.votes;
  trait_record record;
BEGIN
  IF auth.uid() IS NULL THEN
    RAISE EXCEPTION 'Authentication required';
  END IF;

  IF p_selected_option NOT IN ('A', 'B') THEN
    RAISE EXCEPTION 'selected option must be A or B';
  END IF;

  INSERT INTO public.votes (
    user_id,
    question_id,
    selected_option,
    response_time_ms
  )
  VALUES (
    auth.uid(),
    p_question_id,
    p_selected_option,
    p_response_time_ms
  )
  RETURNING * INTO inserted_vote;

  UPDATE public.questions
  SET
    vote_count_a = vote_count_a + CASE WHEN p_selected_option = 'A' THEN 1 ELSE 0 END,
    vote_count_b = vote_count_b + CASE WHEN p_selected_option = 'B' THEN 1 ELSE 0 END,
    total_votes = total_votes + 1,
    updated_at = now()
  WHERE id = p_question_id;

  UPDATE public.profiles
  SET
    total_participation_count = total_participation_count + 1,
    today_participation_count = today_participation_count + 1,
    shell_balance = shell_balance + 1,
    updated_at = now()
  WHERE id = auth.uid();

  FOR trait_record IN
    SELECT trait_key, weight
    FROM public.question_traits

import { create } from 'zustand';
import {
  fetchFeedQuestions,
  submitReaction,
  submitVote,
  type FeedQuestion,
  type FeedSort,
  type OptionSide,
  type ReactionType
} from '../services/questionService';

type FeedState = {
  questions: FeedQuestion[];
  currentSort: FeedSort;
  isLoading: boolean;
  error: string | null;
  loadFeedQuestions: (sort?: FeedSort) => Promise<void>;
  voteOnQuestion: (questionId: string, selectedOption: OptionSide) => Promise<void>;
  reactToQuestion: (questionId: string, reactionType: ReactionType) => Promise<void>;
  clearError: () => void;
};

export const useFeedStore = create<FeedState>((set, get) => ({
  questions: [],
  currentSort: 'popular',
  isLoading: false,
  error: null,

  async loadFeedQuestions(sort = get().currentSort) {
    set({ isLoading: true, error: null, currentSort: sort });
    try {
      const questions = await fetchFeedQuestions(sort);
      set({ questions, isLoading: false });
    } catch (error) {
      set({
        isLoading: false,
        error: error instanceof Error ? error.message : '피드를 불러오지 못했습니다.'
      });
    }
  },

  async voteOnQuestion(questionId, selectedOption) {
    const previousQuestions = get().questions;
    const nextQuestions = previousQuestions.map((question) => {
      if (question.id !== questionId || question.userVote) return question;
      return {
        ...question,
        userVote: selectedOption,
        vote_count_a: selectedOption === 'A' ? question.vote_count_a + 1 : question.vote_count_a,
        vote_count_b: selectedOption === 'B' ? question.vote_count_b + 1 : question.vote_count_b
      };
    });

    set({ questions: nextQuestions, error: null });

    try {
      await submitVote(questionId, selectedOption);
    } catch (error) {
      const previousQuestion = previousQuestions.find((question) => question.id === questionId);
      set({
        questions: previousQuestion
          ? get().questions.map((question) => question.id === questionId ? previousQuestion : question)
          : get().questions,
        error: error instanceof Error ? error.message : '투표 저장에 실패했습니다.'
      });
    }
  },

  async reactToQuestion(questionId, reactionType) {
    const previousQuestions = get().questions;
    const nextQuestions = previousQuestions.map((question) => {
      if (question.id !== questionId) return question;
      const alreadySelected = question.userReaction === reactionType;
      if (alreadySelected) return question;

      return {
        ...question,
        userReaction: reactionType,
        reaction_like_count: question.reaction_like_count + (reactionType === 'like' ? 1 : 0),
        reaction_fun_count: question.reaction_fun_count + (reactionType === 'fun' ? 1 : 0),
        reaction_hard_count: question.reaction_hard_count + (reactionType === 'hard' ? 1 : 0)
      };
    });

    set({ questions: nextQuestions, error: null });

    try {
      await submitReaction(questionId, reactionType);
    } catch (error) {
      const previousQuestion = previousQuestions.find((question) => question.id === questionId);
      set({
        questions: previousQuestion
          ? get().questions.map((question) => question.id === questionId ? previousQuestion : question)
          : get().questions,
        error: error instanceof Error ? error.message : '리액션 저장에 실패했습니다.'
      });
    }
  },

  clearError() {
    set({ error: null });
  }
}));

export type GamificationSnapshot = {
  profile: {

export async function fetchGamificationSnapshot(): Promise<GamificationSnapshot> {
  if (!supabase) {
    throw new Error('Supabase 환경변수가 필요합니다. Browser에서 Supabase 프로젝트 설정을 완료하고 .env를 채워 주세요.');
  }

  const { data: userData } = await supabase.auth.getUser();
  const userId = userData.user?.id;
  if (!userId) {
    return {
      profile: {
        id: 'guest',
        nickname: '게스트 탐험가',
        avatar_url: null,
        shell_balance: 0,
        streak_count: 0,
        total_participation_count: 0,
        today_participation_count: 0
      },
      traits: [],
      island: {
        id: 'guest-island',
        user_id: 'guest',
        island_level: 1,
        island_name: '게스트 섬'
      },
      character: {
        id: 'guest-character',
        user_id: 'guest',
        character_type: 'turtle',
        character_level: 1,
        nickname: '게스트 탐험가'
      }
    };
  }

  const [{ data: profile }, { data: traits }, { data: island }, { data: character }] = await Promise.all([
    supabase.from('profiles').select('*').eq('id', userId).maybeSingle(),
    supabase.from('user_traits').select('trait_key,score').eq('user_id', userId),
    supabase.from('islands').select('*').eq('user_id', userId).maybeSingle(),
    supabase.from('characters').select('*').eq('user_id', userId).maybeSingle()
  ]);

  return {
    profile: {
      id: profile?.id ?? userId,
      nickname: profile?.nickname ?? '섬 탐험가',
      avatar_url: profile?.avatar_url ?? null,
      shell_balance: profile?.shell_balance ?? 0,
      streak_count: profile?.streak_count ?? 0,
      total_participation_count: profile?.total_participation_count ?? 0,
      today_participation_count: profile?.today_participation_count ?? 0
    },
    traits: traits ?? [],
    island: island ?? {
      id: 'guest-island',
      user_id: userId,
      island_level: 1,
      island_name: '새싹 섬'
    },
    character: character ?? {
      id: 'guest-character',
      user_id: userId,
      character_type: 'turtle',
      character_level: 1,
      nickname: '새싹 탐험가'
    }
  };
}
